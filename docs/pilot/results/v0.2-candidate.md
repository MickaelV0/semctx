# v0.2 candidate replay, 2026-09-08

Thirty public changes across three MIT-licensed repositories were replayed with the packaged
Semctx 0.2.0 candidate and Bun 1.4.0. The final run produced thirty reports whose changed-file
sets match Git exactly: ten each for remeda/remeda, nanostores/nanostores and gvergnaud/ts-pattern.
There were no infrastructure failures or untrusted reports. Semctx emitted 23 PASS and 7 WARN
verdicts; every init/index/verify command exited zero. These are observations, not correctness labels.

All thirty ground-truth labels remain UNKNOWN. Scores are null and the research verdict remains
EVIDENCE_MISSING. Accuracy, benefit, adoption, retention and human contribution time are not
measured. The maintainer waived participant studies and the fourteen-day follow-up for this release.

## Retained first attempt and correction

The [first summary](v0.2-first-attempt-summary.json) remains unchanged. That attempt observed all
thirty cases with zero infrastructure failures, but only 29 reports were trusted. Its historical
summary did not expose an untrusted count; absence of that field must not be read as zero.
The raw report classified gvergnaud-ts-pattern-pr-332 as DIFF_MISMATCH: it omitted the deleted
`tests/records.test.ts` and returned eleven changed paths against twelve in Git.

The historical diff parser deliberately discarded deleted files, and an old unit test preserved
that behavior. The correction retains their paths and deleted hunks without inventing graph
symbols that no longer exist. A real Git deletion regression now covers the report path. The final
replay reports all twelve PR-332 paths, including the deleted file. Summary integrity also gained
explicit global and per-repository untrusted counts and refuses efficacy scoring when any report
is untrusted.
