# v0.4.0: refuse unsafe boundary inputs

Semctx 0.4.0 makes unsafe boundary inputs explicit refusals while retaining valid analysis and
the existing verification recovery rules. Publication and delivery are established separately
by the linked release workflow and public artifacts.

## Install or upgrade

Once the public registry exposes the reviewed artifact, install the exact version with:

```bash
bunx semctx@0.4.0 install
```

Runtime/build Bun >=1.4.0 remains the baseline, with TypeScript 5.9.3. Codex CLI 0.147.0 and
Claude Code 2.1.229 retain the existing compatibility pins. Fresh-host delivery requires its
own release evidence; it does not establish activation in already-running sessions.

## What changes

- Corrupt workspace configuration, semantic source and active artifacts are refused instead of
  being formatted, overwritten or interpreted as absent. Explicit initialization still owns
  workspace creation.
- The GitHub Action rejects missing, stale, unsealed or unknown verdicts and unknown failure
  policies. The guarded hook rejects empty, truncated or invalid stdin only when blocking mode is
  established; advisory mode remains non-blocking.
- Stale or unsealed control inputs cannot authorize autonomous writes. Traversal, impact and
  explanation require matching observed freshness seals; the separate verification/recovery
  admissibility table is unchanged.
- Analyzer I/O and external-source confinement failures remain visible producer failures. Valid
  TypeScript analysis retains libraries, resolution, types, symbols, JSDoc and cross-file calls.
  Repository directory aliases use the same physical path identity for confinement and facts.
- The optional CocoIndex adapter probes `ccc version`, passes search queries after `--`, applies
  named process budgets and distinguishes valid empty results from invalid output and process
  failure. Provider candidates remain diagnostic-only without an exact source seal.
- Reconciliation uses the canonical artifact schema and hash checks. Git capture reports an unborn
  repository separately from a failed HEAD observation.

These are intentional rejection changes for unsafe inputs accepted by earlier versions. Existing
valid versioned artifact bytes and historical capsule formats are not relabelled, and no proof,
authority or conformance requirement is weakened.

## Evidence and limits

The [release PR](https://github.com/hoklims/semctx/pull/209) records source validation, selected
multi-OS CI, independent aggregate proof review and the N-1 proof gate. Publication requires the
existing release workflow, registry read-back and fresh-host delivery. The public demo reports
its own artifact identity and replay status; source validation alone cannot establish these.

### Observed publication — 2 October 2026

The [release workflow](https://github.com/hoklims/semctx/actions/runs/36966954120) completed source
verification, signed npm publication, public registry read-back, delivery on two fresh host
profiles and stable/GitHub promotion. The annotated tag, public npm `gitHead` and stable channel
identify `d10dbb9e264fec2393d1a444777702dee84553c4`; its tree equals the reviewed PR candidate.
Codex CLI 0.147.0 and Claude Code 2.1.229 each installed 0.4.0 and passed bundled CLI/MCP smokes.

The downloaded public tarball has SHA-256
`8fb587e9c673f32d040b85984133f2087c1604f5500da34489e85c6f71d2f4c6`, exactly matching the immutable
CI package; npm's SHA-512 integrity also matches. Its public-package replay completed with the
expected **WARN and 3/3 cases**, using the same runtime digest as the candidate replay.

The fresh aggregate source review and unchanged N-1 gate accepted the exact candidate with eight
explicit per-path witness waivers, recorded in the release PR. The earlier failed local suite and
PROOF_WEAK audit were retained rather than relabelled. Already-running sessions remain
`SESSION_VERSION_NOT_EXPOSED`: open a new Codex task, or reload/restart Claude Code.

Mac/lobby performance remains **NOT_MEASURED**. The scheduler approach tracked by issue #205 received
a **NO_GO** under its declared memory budget. The release makes
no adoption, efficacy, human-time or statistical performance claim; those outcomes remain
**NOT_MEASURED**. Oh My Pi support remains experimental. Optional providers are not a replacement
claim, and the qualified change-validation profile remains future work under HOK-892 without a promised release
version.

## Publication and rollback

The release workflow must bind the tag, npm tarball, GitHub Release,
stable branch and fresh-host delivery to the same reviewed candidate before promotion.

Rollback uses the documented explicit installation of `semctx@0.3.9` and the immutable
`v0.3.9` plugin tag.
