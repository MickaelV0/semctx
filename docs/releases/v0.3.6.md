# v0.3.6: read-only host diagnostics and confined delivery

Semctx 0.3.6 makes plugin discovery and installation safer across Codex and Claude Code. It keeps
Claude diagnostics declarative, completes every available host preflight before a multi-host install
mutates either host, and preserves raw filesystem identities until confinement has accepted them.

## Install or upgrade

Semctx 0.3.6 requires Bun >=1.4.0. Pin the release when reproducibility matters:

```bash
bunx semctx@0.3.6 install
```

Plugin installation does not activate an already-running session. Open a new Codex task, or run
`/reload-plugins` in Claude Code and restart if reload fails.

## Read-only diagnostics

`plugin-status` and install planning read Claude Code's declarative plugin metadata directly. They do
not launch Claude Code merely to list plugins, so a dry run does not create first-use profile files.
Malformed, linked, incomplete or changing metadata remains `UNKNOWN`; absence is reported only when
the corresponding inventory is safely known to be empty.

Delivery, activation and observation remain separate. An installed plugin is not assumed loaded,
approved or observed, and Semctx does not grant hook or plugin trust on the user's behalf.

## Installation and confinement

An all-host apply performs a fresh read-only validation of every requested host before the first
marketplace or plugin mutation. Each host is checked again at its own apply boundary. A conflict or
unsafe second observation therefore leaves both hosts and the repository setup untouched.

Host paths, configured homes, cache versions and marketplace locations retain their raw identity
until local-shape, traversal, endpoint and confinement checks finish. Local aliases are accounted for
where exclusion requires both lexical and canonical paths; inventory reads still refuse links and
reparse points. Whitespace, control characters, network paths and ambiguous version segments never
select a cleaned sibling silently.

## Compatibility and limits

The tested baseline remains Bun 1.4.0 or newer, Codex CLI 0.147.0 and Claude Code 2.1.229:
https://github.com/hoklims/semctx/actions/runs/34664142432

Other host versions are **UNKNOWN** until tested. Oh My Pi support remains **experimental**. Adoption,
retention, contribution time and human comprehension remain **NOT_MEASURED**. A green source or CI
candidate does not establish registry availability, running-session activation, trust grants or
observed efficacy.

## Publication evidence and rollback

At source-candidate stage, the npm package, immutable tag, `stable` plugin channel and GitHub Release
may not exist yet. The tag-driven workflow must publish the exact reviewed commit, verify npm
`gitHead`, prove isolated Codex and Claude installation with CLI and MCP smokes, then advance
`stable` and create the GitHub Release.

For rollback, pin the last public release with `bun add --global semctx@0.3.5` and use the immutable
`v0.3.5` plugin tag. That release does not contain these diagnostic, ordering and confinement fixes;
moving `stable` manually is not a rollback procedure.
