# v0.4.1: bounded large-diff MCP transport

Semctx 0.4.1 fixes a reproducible stdio disconnect when an inline diff exceeds the SDK's former
10 MiB message-buffer default. The CLI and Codex/Claude plugins remain one lockstep release.

## What changes

The MCP entrypoint supplies an explicit 32 MiB wire-message bound to the existing dual-era SDK
factory. A larger serialized message is rejected with a payload-free stderr diagnostic directing
callers to omit `gitDiff` and let Semctx read the diff from Git. The bound includes the JSON
envelope and escaped content; it is not a total process-memory guarantee.

The ordinary `semctx_verify_change({ repositoryRoot })` path retains its Git-backed identity and
analysis. An explicitly provided diff still does not prove its source identity: conservative
findings such as `SOURCE_IDENTITY_ABSENT` remain visible. No coverage, business-correctness,
freshness, authority or conformance guarantee is upgraded by this transport fix.

## Install or upgrade

After the canonical release workflow exposes the reviewed artifact:

```bash
bunx semctx@0.4.1 install
```

Bun >=1.4.0 remains required. Codex 0.147.0 and Claude Code 2.1.229 retain the existing compatibility
pins. Installation does not reload an active session: start a new Codex session or reload the
Claude plugin before attributing live behavior to the new version.

The existing [host baseline delivery proof](https://github.com/hoklims/semctx/actions/runs/34664142432)
supports those compatibility pins; it is not a delivery receipt for 0.4.1. Oh My Pi remains an
experimental consumer without the two-host delivery attestation. A rollback installs the previous
published version through the native host mechanism instead of modifying a locked cache.

## Evidence and limits

The regression tests exercise a real SDK client with an inline diff above 10 MiB, a follow-up
request on the same connection, an overflow above 32 MiB, a stderr-only fallback diagnostic and
the existing modern/legacy stdio boundary. The installed 0.4.0 runtime reproduced the disconnect
on a 17,664,355-byte diff; the corrected runtime processed it and preserved the ordinary Git-path
report. Publication, registry identity, stable promotion and fresh-host delivery are established
separately by the annotated tag's canonical release workflow.

The [versioned GitHub Release](https://github.com/hoklims/semctx/releases/tag/v0.4.1) and
[npm package](https://www.npmjs.com/package/semctx/v/0.4.1) are publication targets until registry
read-back succeeds. The [public demonstration](https://hoklims.github.io/semctx/demo/) carries its
own artifact identity, which may still refer to the previous published package. Adoption,
retention and human contribution time remain NOT_MEASURED; untested hosts and live-session
activation remain UNKNOWN until observed.
