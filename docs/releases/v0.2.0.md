# v0.2.0: reproducible first use and local evidence

Semctx now has a packaged three-case walkthrough and a contributor path that diagnoses setup,
runs a named test scope, and demonstrates a real failing then passing regression in a temporary
copy. The full contributor check still invokes the existing canonical repository gate.

`semctx feedback` records voluntary local answers against an exact finding. Duplicate answers are
idempotent; conflicting answers require an explicit update. Records can be listed, inspected and
removed. `feedback export` publishes only aggregate codes and counts. `semctx support` produces a
small allowlisted diagnostic report. Neither command sends data anywhere.

The public demo pairs the combined diff with its real report and an explicit runtime-behavior
limit. The replay tool freezes artifact/runtime identities and a thirty-change public corpus,
compares changed-file and one-hop import baselines, and retains failures. All current labels are
UNKNOWN: accuracy, benefit, adoption, retention and human contribution time remain unmeasured.
The maintainer explicitly waived participant studies and the fourteen-day follow-up for v0.2.

The public replay exposed a historical diff-parser defect: deleted files disappeared from
`changedFiles`. The correction retains their paths and marks whole-file changes without inventing
deleted symbols. Pilot summaries distinguish reports rejected by integrity checks from failures
to execute and refuse efficacy scores when either is present.

Oh My Pi can consume the existing nested plugin through an Agent-Plugins manifest, a portable
embedded CLI shim and one shared opt-in Git guard. The existing catalogue pins the exact release
tag. OMP remains experimental; its recipe is separate from Codex/Claude stable-delivery attestation.
Remove an obsolete OMP installation after reviewing the [migration inventory](../integrations/omp.md)
before installing the standard package. No OMP/Bun fork or mirror is needed.

The CLI and plugins require Bun >=1.4.0. Their existing public verification and MCP contracts,
default advisory guard behavior and no-executor boundary remain in force. New feedback/support
formats have independent v1 schemas; the verify-report v1 reader accepts additive fields.

Release publication follows the existing annotated-tag pipeline: verification, exact npm
`gitHead`, stable promotion, GitHub Release, then isolated delivery checks for both supported hosts.
The [release workflow](https://github.com/hoklims/semctx/actions/workflows/release.yml) is the source
for publication status. A built candidate, replay result or green local test is not publication.

For rollback, pin the preceding CLI/plugin release, v0.1.20. Do not force the shared stable branch.
Feedback state is optional local data; inspect and export it before explicitly removing records.
