# v0.3.0: recover an index and resume from recorded evidence

Semctx 0.3.0 adds explicit recovery and continuation tools, plus a reviewed path for changing an
existing repository's file-selection configuration. Installation alone does not change a repository's
configuration, authored declarations or recorded verification state.

## Install or upgrade

Semctx 0.3.0 requires Bun >=1.4.0:

```bash
bunx semctx@0.3.0 install
```

Open a new Codex task after installation, or run `/reload-plugins` in Claude Code and restart if
reload fails. Installation does not activate new runtime bytes in an already running session.

## What changed

An outdated verification baseline can no longer prevent the explicit operation that repairs it.
`semctx index --record` rebuilds the index and records the current binding, while retaining failed
rebuild evidence and refusing unsafe inputs. An ordinary rebuild still does not validate historical
evidence or mark a change approved.

`semctx control handoff explain --hash <sha256>` produces a continuation report from an existing
Handoff v2 capsule and the current repository. It explains recorded intent, planned work, remaining
obligations, known limitations and whether the capsule still applies. The matching MCP tool exposes
the same application report. Changed source or missing current evidence remains visible and can
refuse resumption. A packaged walkthrough exercises capture, explanation, repository drift and
refused resumption without modifying the contributor's checkout.

Index lifecycle coverage now exercises file edits, renames and deletion, branch changes, linked
worktrees, repeated requests through a persistent MCP connection and real process interruption.
Interrupted SQLite replacement retains the previous committed snapshot or the complete new one.
These checks cover process termination; they do not establish behavior under power loss.

The new `semctx migrate config` command makes file-selection changes explicit. A read-only plan
shows the old and proposed selections. Applying requires that plan's digest, records an exact
backup and refuses stale inputs. Restoration names the recorded run and refuses unrelated current
configuration. The command preserves authored `.sem` files, the index and verification baseline;
the repository must be rebuilt and verified after the configuration changes. See the
[configuration reference](../reference/configuration.md) for the full procedure and refusal rules.

## Compatibility and limits

The CLI, MCP package and both supported plugins advance together to 0.3.0. Existing configuration
continues to work; migration is opt-in. The continuation report and migration report are additive,
versioned contracts. No provider is removed and no execution authority is added.

Benchmark collection now retains per-process CPU and peak RSS alongside semantic fingerprints.
The hosted Windows, Linux and macOS runs use synthetic fixtures. The required `lobby` baseline on
an Apple Silicon Mac remains **NOT_MEASURED**, and this release claims no measured performance
gain, incremental-indexing implementation or completed performance budget.

Human comprehension, time saved, adoption and retention remain **NOT_MEASURED**. A successful
walkthrough demonstrates executable behavior, not those outcomes. Oh My Pi remains experimental
and outside the Codex/Claude delivery attestation.

## Publication evidence and rollback

The [tag-driven release workflow](https://github.com/hoklims/semctx/actions/workflows/release.yml)
verifies the annotated tag, publishes the exact npm tarball, checks its `gitHead`, advances `stable`
without force, creates the GitHub Release and then verifies installation through Codex and Claude
in isolated homes. The workflow result is the authority for publication and host delivery; source
code and local verification alone do not establish either result.

For a runtime rollback, pin the CLI with `bun add --global semctx@0.2.1`. The `install` command
always follows the plugin `stable` channel, even when the CLI itself is pinned. To pin the plugins,
replace only the Semctx marketplace in the relevant host profile with the immutable release tag:

```bash
codex plugin remove semctx-control@semctx-stable --json
codex plugin marketplace remove semctx-stable --json
codex plugin marketplace add hoklims/semctx --ref v0.2.1 --json
codex plugin add semctx-control@semctx-stable --json
```

For a Claude user-scope installation:

```bash
claude plugin uninstall semctx@semctx-stable --scope user --keep-data
claude plugin marketplace remove semctx-stable --scope user
claude plugin marketplace add hoklims/semctx@v0.2.1 --scope user
claude plugin install semctx@semctx-stable --scope user
```

Use the scope of the actual installation, then open a new session. This procedure was replayed
in isolated Windows profiles with Codex 0.154.0-alpha.6.2 and Claude Code 2.1.266. Both marketplace
checkouts resolved to `abb39a6b46a74c6538556a90d6ba95e8fb06eea4`; all four runtime artifacts matched
that tag and both embedded CLIs reported 0.2.1. This is a local rollback observation, separate from
the pinned-host release-delivery check. Do not force `stable` or rewrite a published tag.
Configuration restoration is a separate explicit operation using the migration run recorded
before applying the proposal. Preserve its artifacts.
