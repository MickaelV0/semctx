# v0.3.7: Codex planning without profile writes

Semctx 0.3.7 removes native Codex version and plugin-list probes from install preflight and default
plugin diagnostics. Those nominal reads create `CODEX_HOME/tmp/arg0` in Codex CLI 0.147.0 and 0.155.1.
Semctx now reads declarative configuration and physical plugin metadata directly.

## Install or upgrade

The release requires Bun >=1.4.0. Once registry publication is verified, the pinned command is:

```bash
bunx semctx@0.3.7 install
```

Open a new Codex task after installation. In Claude Code, reload plugins and restart if reloading
fails. Installation does not prove an already-running session loaded the new plugin.

## Planning and diagnostics

Codex configuration is read from its selected physical profile. Approved project configuration
can override user plugin settings; an unapproved project never contributes effective configuration.
All configured marketplaces are inspected in Codex's supported manifest order. Malformed or linked
metadata, unsafe source identities, changing bytes and changing directory identities refuse the
plan. A proven empty profile is reported as empty without creating its first-use files.

The supported view is the bare plugin CLI invocation controlled by Semctx. Relevant system or
legacy settings, selected profiles, unresolved managed preferences and ancestor overrides remain
unsupported and refuse installation. Desktop cloud policy and running-session flags are not
inferred from local registration files.

The active cache directory is kept separately from the plugin's declared version. A valid `local`
development override stays visible in diagnostics and blocks stable installation with an explicit
conflict. No third-party content is replaced to resolve that conflict.

Host detection uses a PATH lookup. Install JSON exposes the host version as `null` when unobserved;
native command compatibility is not inferred from an executable's presence. Installed, configured,
loaded, approved and observed states remain separate, and unavailable evidence stays `UNKNOWN`.

## Compatibility and limits

The two-host release baseline remains Bun 1.4.0, Codex CLI 0.147.0 and Claude Code 2.1.229:
https://github.com/hoklims/semctx/actions/runs/34664142432

Codex declarative metadata was also exercised with CLI 0.155.1 in isolated local fixtures. This
narrow check does not establish full compatibility with other host versions. Oh My Pi support
remains experimental. Adoption, retention, efficacy and human time remain `NOT_MEASURED`.

## Publication and rollback

Source acceptance, npm publication, plugin-channel promotion and host delivery are separate gates.
The immutable tag workflow verifies the public npm archive and Git identity, installs both hosts
in isolated profiles, runs CLI/MCP smokes, then advances `stable` and creates the GitHub Release.

For rollback, pin public `semctx@0.3.6` and the immutable `v0.3.6` plugin tag. That version lacks the
Codex read-only planning correction. Do not move `stable` manually as a rollback.
