# v0.3.8: lower TypeScript extraction memory

Semctx 0.3.8 reduces the memory allocated to JSDoc syntax trees in the TypeScript extraction
context. It uses TypeScript 5.9.3's `ParseForTypeErrors` mode, also used by the compiler, on a
standard host. Types, libraries and module resolution remain enabled. Semctx still reads raw
JSDoc comments and semantic markers directly from the source text.

## Install or upgrade

The release requires Bun >=1.4.0. Once registry publication is verified, the pinned command is:

```bash
bunx semctx@0.3.8 install
```

Open a new Codex task after installation. In Claude Code, reload plugins and restart if reloading
fails. Installation does not prove an already-running session loaded the new plugin.

## Measured scope

Matched Windows probes used Bun 1.4.2 and TypeScript 5.9.3, with the same input files, options and
dependencies for each old/new pair. Native process peak working set includes worker threads;
every probe was bounded to 35 seconds and 1.5 GiB. Full structured extraction JSON was compared
byte for byte, including ordering and call targets.

| Input | Workers | Peak RSS before → after (MiB) | Process duration before → after (s) |
| --- | ---: | ---: | ---: |
| `greeting`, `cart`, `pricing` | 1 | 304.25 → 262.55 | 3.295 → 0.680 |
| Same three independent modules | 2 | 553.27 → 503.74 | 0.981 → 0.896 |
| Frozen extractor, one root | 1 | 321.26 → 295.89 | 0.854 → 0.736 |
| TSX, aliases and shared declarations | 1 | 279.46 → 261.46 | 0.656 → 0.616 |
| Repository example, eight roots | 1 | 288.86 → 262.26 | 0.740 → 0.626 |

Each pair produced identical facts. These are single local observations, not statistical speed
estimates or a Lobby benchmark. The reported Lobby crash was not reproduced. Each explicit
worker still creates its own semantic context, so parallelism remains a conditional memory
amplifier. The default worker count and DTOs are unchanged.

Regression witnesses cover the actual optimized context, raw JSDoc, markers, TSX, aliases,
shared declarations, inter-file targets and ambiguous calls. Bypassing the optimized context or
removing extracted symbols fails the new tests. The correction also restores the existing
compatibility test's missing-all-provisioning fixture under the current multi-job CI.

## Compatibility and limits

The two-host baseline remains Bun 1.4.0, Codex CLI 0.147.0 and Claude Code 2.1.229:
https://github.com/hoklims/semctx/actions/runs/34664142432

Other host versions and activation in existing sessions remain `UNKNOWN`. Oh My Pi support
remains experimental. Adoption, retention, efficacy and human time remain `NOT_MEASURED`.
The site evidence is regenerated from a completed local three-case replay of the 0.3.8 candidate
bundle. It retains candidate phase and unverified source authority; this is not registry or
publication evidence. Historical observations are not relabelled as a new execution.

## Publication and rollback

Source acceptance, npm publication, registry availability, host delivery and promotion remain
separate gates. The tag workflow verifies the immutable public package and Git identity, proves
fresh Codex and Claude installations, then advances `stable` and creates the GitHub Release.

For rollback, pin public `semctx@0.3.7` and the immutable `v0.3.7` plugin tag. That version keeps
the previous memory allocation behavior. Do not move `stable` manually as a rollback.
