## Cause and correction

The real Semctx witness has 889 tracked files and 4,366 indexed graph nodes. A continuation explanation performed four verification captures, including two from semantic baseline inspection. Each materialized file launched `git hash-object`: 3,556 launches consumed 180.462 of the 185.349 seconds in the phase profile.

The service now hashes the already-read regular-file payload locally only when it contains no CR byte and resolved Git attributes establish no active filter, ident expansion or working-tree encoding. It streams file contents through the existing hashes, retaining only path/attribute metadata across files. SHA-1 and SHA-256 Git storage identities retain the same blob framing. Conversion-bearing content, symlinks and sparse entries keep the existing Git path.

Named Git attribute output conflates unset states with literal filter names such as `unset` and `unspecified`. An additional `check-attr --all` observation distinguishes genuinely unspecified attributes; ambiguous explicit transformer declarations retain Git hashing. Metadata is reobserved after hashing, and missing, malformed or changed observations refuse capture. No cache is shared across captures.

Git remains the conversion oracle: [hash-object](https://git-scm.com/docs/git-hash-object) documents path-selected input filters, and [gitattributes](https://git-scm.com/docs/gitattributes) documents conversion attributes. The implementation does not reimplement those conversions.
