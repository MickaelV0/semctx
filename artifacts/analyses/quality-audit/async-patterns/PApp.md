# Async Patterns — PApp

## Summary
Reviewed App-plane production source (`app-services`, `apps/cli`, `mcp-server`, `context-engine`, `repository-store`; tests skipped). Happy-path store lifetime in `app-services` is mostly disciplined (`try/finally` or catch-close; `indexRepositoryAsync` does not hold SQLite while TypeScript workers run). Plugin-delivery and CLI-compatibility probes already kill children with `timeout` + `maxBuffer`. Worst issue is a WAL writer held across `await fetchProviderCandidates` with no abort, and CLI `context prepare` missing `finally` — a hung provider or SIGINT leaves `-wal`/`-shm` sidecars that make MCP immutable readers refuse the database. Git `spawnSync` on verify/freshness/control has no timeout, so a lock wait blocks the MCP stdio event loop indefinitely.

- Missing-await suspects: 3 (`void main()` is caught + `process.exit`; 2× `void Promise.resolve(observer)` = ASYNC-PAPP-09). CLI `dispatch` returns thenables (`runIndexAsync` / `runSetupAsync` / `runContextPrepare`) — not missing await
- Index-worker: `indexRepositoryAsync` awaits `analyzePlaneARuntimeAsync` then opens the store only in `completeRepositoryIndex` (`indexing.ts:166` then `:295`). Workers themselves live in `ts-analyzer` (PA). MCP `setupTool` calls sync `setupRepository` (no workers)
- Unclosed-handle pattern: `app-services` readers generally `finally close`; CLI inspect/task/bench/semantic/context do not; MCP `inspectTool`/`facts()` do
- Blocking sync I/O on MCP hot path: every `runVerify` / `controlStatus` / `indexHealth` uses `spawnSync` git + sync SQLite loads

## Recommendations
1. Never hold a WAL writer across await. Close (or never open) before provider fetch; persist with a short writer. Put `try/finally close` on every CLI `openStore`.
2. Give every git/host `spawnSync` the plugin-delivery contract: timeout, maxBuffer, `--no-optional-locks`. Map timeout to a typed error so MCP stdio cannot wedge.
3. Stop detaching unbounded Codex cleanup processes; if deferred work is required, a bounded child with kill-on-deadline, not 12h `unref`.
4. Add SQLite `busy_timeout`, treat checkpoint-busy as retry not “close then throw”, and recover WAL on the MCP read path (or route reads through a recovering writer) so leftover sidecars are not a permanent inspect outage.
5. Add `AbortSignal` to `fetchProviderCandidates`. Keep `indexRepositoryAsync`’s “analyze first, store last” shape; if workers gain cancel in PA, thread the signal from CLI/MCP.
