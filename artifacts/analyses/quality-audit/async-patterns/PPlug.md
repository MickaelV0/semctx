# Async Patterns — PPlug

## Summary
Reviewed plugin hooks (`plugins/shared/hooks/semctx-lifecycle.mjs`, Claude `semctx-guard.mjs`, host `hooks.json`), `scripts/` (verify-pr, delivery proof, plugin/CLI build, compatibility, multicore bench, stress shell), `packages/github-action/src/adapter.mjs`, `packages/eval/src`, and `packages/test-fixtures/src` (source only; skipped tests, `dist/`, `typescript-lib`). No SQLite and no index-worker races in this plane: eval/fixtures are pure sync, the lifecycle ledger is append-only with `fsync`+`closeSync`, and `prove-stable-delivery.ts` already bounds MCP spawn with request/exchange deadlines plus SIGKILL. Worst issue is the Claude PreToolUse guard: fully sync (correct for a command hook) but it fingerprints the whole worktree with unbounded `spawnSync`/`execFileSync`/`readFileSync` and neither the git children nor `hooks.json` have a timeout, so a hung git or a large repo stalls the host. Next is `verify-pr` / the bench: `Bun.spawn` without timeout/kill, unlike the delivery-proof runtime.

## Metrics
- Files read: 18 (authored PPlug source; lifecycle host copies not double-counted)
- Findings: 5 (P0: 0 / P1: 1 / P2: 4 / P3: 0)
- Spawn sites: 25 — guard 18 (`spawnSync` 6 + `execFileSync` 12, none with `timeout`); `verify-pr` 2 `Bun.spawn` (no timeout/kill); bench 2 `Bun.spawnSync` (no timeout); delivery proof 1 `Bun.spawn` (kill + SIGKILL + bounded `exited`) + 2 `Bun.spawnSync` (`timeout: HOST_COMMAND_TIMEOUT_MS`)
- SQLite write sites: 0
- Missing-await suspects: 3 (`void FileSink.write` ×2, `void FileSink.end` ×1)
- Hook model: lifecycle + guard are sync Node command hooks (host contract). Lifecycle: no child processes, append-only ledger (`openSync`/`writeSync`/`fsyncSync`/`closeSync` in `finally`, concurrent observations append rather than RMW). Guard: blocking git + whole-tree `readFileSync` on PreToolUse. `semctx-control` has no guard.
- Eval / github-action adapter / test-fixtures / compatibility / plugin-build: one-shot sync I/O or fully `await`ed `Bun.build`/`Bun.write`; not hot paths. Stress shell has no per-`semctx` timeout (manual).

## Recommendations
1. Treat PreToolUse duration as a product invariant: every git child in `semctx-guard.mjs` needs `timeout`, and `hooks.json` must declare a hook `timeout` so a hung `git` cannot pin the host. Do not “fix” this by making the guard async unless the process stays alive until the fingerprint finishes.
2. Reuse the delivery-proof spawn contract (`timeout` on `spawnSync`; `kill` then `SIGKILL` on `Bun.spawn`) in `scripts/verify-pr.ts` and `scripts/benchmark-multicore-index.ts` — those are the only unbounded script spawns left.
3. Stop `process.exit` after `stderr.write` in the guard; lifecycle already has the portable pattern (pin `exitCode`, return).
4. Await `FileSink.write`/`end` in `defaultMcpHandshake` so a backpressured stdin cannot look like a server timeout.
