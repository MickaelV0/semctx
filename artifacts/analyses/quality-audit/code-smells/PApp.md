# Code Smells — PApp

## Summary
Inventoried all App-plane `src/` (skipping tests): `app-services` (27 files, 12116 loc), `apps/cli` (4616), `mcp-server` (4496), `context-engine` (2949), `repository-store` (676). Health is mixed: `plugin-status` and `control-tools` are thin over `app-services`, and `repository-store` is a 500-line persistence port, not a god object. The partition is dominated by three confirmed god files (`plugin-delivery.ts` 2093, `reconciliation-index.ts` 2039, `apps/cli/src/commands/install.ts` 1522) plus a 619-line MCP registrar. Worst issue is DRY drift: `install.ts` recopies `plugin-delivery` host-source helpers and omits userinfo stripping, so install and `plugin-status` can disagree on whether a marketplace is Semctx.

## Recommendations
1. Land SMELL-PAPP-01 first: one `normalizeGitSource` / bundle list / version-segment regex. Install vs `plugin-status` must not diverge on marketplace identity.
2. Split the three god files along existing seams (host query / attestation / report; bind / plan / reconcile / proof; Codex vs Claude mutations + deferred cleanup). Do not grow `app-services` while splitting — architecture already called the package a god.
3. Collapse CLI/MCP copy-paste (`semantic-tools` ↔ `semantic.ts`, `prepareTaskTool` ↔ `context.ts`) into app-services use cases; transports stay argv/JSON. Layer ownership is already filed.
4. Delete the second unified-diff parser; route `verify-diff` through `parseObservedDiffHunks` / `parseUnifiedDiffBytes`.
5. Finish MCP registrar extraction so `createSemctxServer` is a list of `register*Tools`, not a 600-line switch.
6. Replace `index-health` type-predicate soup with Zod parses already owned by graph/claim schemas; unexport `isLocalFilesystemPath`.
