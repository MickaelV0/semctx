# Security — PA

## Summary
Reviewed Plane A source only (`ts-analyzer`, `python-analyzer/src`, `plane-a-internal`, `workspace-analyzer-internal`, `cocoindex-adapter`), skipping tests and excluded trees. SECURITY.md’s argv-spawn claim holds here: the only `Bun.spawnSync` sites pass arrays (no shell string); there is no SQL and no in-process `fetch`/`eval`/`new Function`. Discovery and the workspace walker skip symlink children (CWE-59) and reject `..` / absolute workspace members; Python extraction is Lezer-only and rejects `..` in `relPath`. Untrusted file contents are parsed, not executed, inside this process. Worst issues: `ccc search` puts the caller query in argv without `--` (flag injection, real callsite in `context-engine`), and `ts.createProgram` uses the default `ts.sys` host so imports / `/// <reference path>` can read files outside the configured root — contradicting “reads … under the configured root”.

## Recommendations
1. Jail the TypeScript `CompilerHost` to `repoRoot` (regular files, no symlink follow, no FIFO). This restores the containment discovery already documents at `discovery.ts:178-180` and that the worker DTO validator already assumes.
2. Fix `ccc` argv to `--` + clamped limit; treat `CocoIndexCandidateProvider` as an untrusted-child boundary (timeout, command allowlist, schema’d JSON, contained `filePath`).
3. Cap discovery/analyze file reads. Keep python-analyzer / plane-a-internal / workspace member matching as they are on exec and `..` escape.
4. Do not load a full YAML/JSON merger for frontmatter; the hand parser is the right shape — just keep keys off `__proto__` if that object is ever spread.
