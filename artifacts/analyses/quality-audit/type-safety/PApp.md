# Type Safety — PApp

## Summary
Reviewed App-plane `src/` (tests skipped): `app-services`, `apps/cli`, `mcp-server`, `context-engine`, `repository-store` (90 files). Health is mixed-good on the type *language*: no `any`, no `as any`, no `@ts-ignore` / `@ts-nocheck` / `@ts-expect-error`. Worst issue is the persistence boundary — `repository-store` loads the graph, claims, and pack blobs with SQLite row casts and `JSON.parse as T`, so `NodeKind` / `ClaimKind` exhaustiveness downstream is unsound. Next is a fail-closed drift: `assertTargetProposalContained` trusts git bytes as `TargetArchitectureArtifactV1` while `target-review.ts` runs `parseArtifact`. Transports that already Zod-parse (CLI control JSON, MCP tool output, `config.json`) are in better shape.

## Recommendations
1. Close TYPE-PAPP-01/03 first: the store is the only place the graph becomes a typed value. Shared kind enums + Zod (or the existing `index-health` predicates) on `rowTo*` and on task/pack payloads. Callers must not see a forged `NodeKind`.
2. Make reconciliation use the same target/attestation decoders as review and indexing (`parseArtifact`, `parseSealedAttestationIndex`). Two git-show parsers is how TYPE-PAPP-02 exists.
3. Replace hand-rolled snapshot decoders (`parseIndexedControlSnapshot`, `parsePlaneAIndexSnapshot`) with Zod. Keep hash-mismatch as refine, not as a license to `as unknown as`.
4. Delete generic `parseJsonArray<T>` and the MCP `ExecutionStateSchema` / `authorize_step` double-cast. Host JSON stays `unknown` until fields are checked; tool inputs stay inferred from a real schema.
5. Add `never` defaults on `VerifySource` and `PathKind`. Do not grow `as unknown as` envelope helpers; if they stay, the Zod parse is the contract, not the cast.
