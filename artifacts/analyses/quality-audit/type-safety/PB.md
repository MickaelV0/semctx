# Type Safety — PB

## Summary
Reviewed all 45 Plane B + `core` source files (`packages/core`, `semantic-model`, `semantic-dsl`, `semantic-engine`; tests skipped). The partition is strict (`noImplicitAny`, `noUncheckedIndexedAccess`) and clean of `any`, `as any`, `as unknown as`, and `@ts-ignore` / `@ts-nocheck` / `@ts-expect-error`. Target artifacts go through Zod after `JSON.parse`; `lifecycleForVerdict` is an exhaustive union switch. Worst issue is `readHandoff`: `JSON.parse` plus a type predicate that does not actually prove `HandoffCapsule`, so a hand-edited/stale file is resumed as typed data.

## Recommendations
1. Put Zod at every JSON file boundary in this partition: handoff capsule first, then journal NDJSON + owner. Keep the refinement tokenizer’s `JSON.parse` of a quoted token — it already narrows to `string`.
2. Infer `TargetArchitectureArtifactV1` from a `normativeStatus` discriminated union so `accepted` has `supersedesRef` in the type. That deletes two `!` and four `as TargetArchitectureArtifactV1`.
3. Split `SemanticNodeKind` so `"change"` cannot inhabit `nodes[]`. Then delete the `as Exclude<…, "change">` in `finalizeNode`.
4. Ban `as never` / post-`safeParse` `as T` in parsers; `provenance` in the same function is the pattern.
5. Leave index `!` under `noUncheckedIndexedAccess` unless a helper (`at` + check) is cheaper than the bang. Do fix the optional-method `!` on the production FS adapter.
