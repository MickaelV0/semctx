# Error Handling — PApp

## Summary
Reviewed App-plane production `src/` (`app-services`, `apps/cli`, `mcp-server`, `context-engine`, `repository-store`; tests skipped). Control queries, handoff persist, plugin-delivery probes, and MCP `ToolRegistrar` are mostly fail-closed: STALE/UNSEALED refuse high-risk envelopes as `INDEX_STALE`, spawn exceptions become `code: 1`, handler throws become `isError` catalogue errors (ADR 0012). Store writer `close()` throws on busy checkpoint rather than swallowing it; indexing/MCP prepare attach suppressed close errors. Worst issue is the primary product gate: `runVerify` keeps `PASS` (CLI exit 0, MCP success-shaped) when freshness is STALE/UNSEALED but every reason is classified admissible, while Plane C withholds `canRunHighRiskControl`. Next is `captureTrackedWorkingDiff` hashing an empty diff when `git rev-parse HEAD` fails inside a worktree — the sibling `captureGitState` path refuses that shape.

## Recommendations
1. Split verify’s index-binding gate: UNSEALED always BLOCK; WORKING_DIFF_MISMATCH may stay admissible; other STALE reasons must not green-light PASS. Make unknowns affect CLI exit / MCP consumers.
2. Align `captureTrackedWorkingDiff` with `captureGitState`: empty bytes only for a proven unborn repo; every other git failure is `GIT_ERROR`. Wrap every product git `spawnSync` like `defaultRunQuery`.
3. Stop empty-catch dummy success on the verify/pack path (`git log` → unknown; provider → typed unavailable, not `[]`).
4. Put real `Error.cause` on `SemctxError` and on `FRESHNESS_PROBE_FAILED`; map store `JSON.parse` failures to `STORE_ERROR` so MCP does not call them `INTERNAL_ERROR`.
5. Leave writer checkpoint-busy as a thrown `STORE_ERROR` (do not swallow). Recovery of WAL sidecars is an async/lifetime issue already filed elsewhere — do not hide the close error to paper over it.
