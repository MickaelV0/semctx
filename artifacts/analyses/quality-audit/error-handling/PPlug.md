# Error Handling — PPlug

## Summary
Reviewed plugin hooks (`plugins/shared/hooks/semctx-lifecycle.mjs`, Claude `semctx-guard.mjs`, both `hooks.json`), `scripts/` (verify-pr, delivery proof, compatibility, plugin/CLI build, multicore bench, stress shell), `packages/github-action` (`adapter.mjs` + `action.yml`), `packages/eval/src`, and `packages/test-fixtures/src` (source only; skipped tests, `dist/`, `typescript-lib`, lifecycle host copies). Lifecycle is the healthy pattern: advisory, never `process.exit`, corrupt ledger → `invalid` not a greener session, outer catch is a silent no-op so the host cannot be blocked. Guard `guardDecision` and fingerprint failures are fail-closed (`currentState = null` → block). Worst issue is the enabled PreToolUse guard itself: invalid stdin `JSON.parse` exits 0 before enablement or isolation checks, so a truncated Bash payload fails open. Next is the Action adapter, which is the sole job gate after `verify diff --fail-on none` and treats any non-BLOCK/non-WARN verdict as success.

## Metrics
- Files read: 20 (authored PPlug source + `action.yml` / both `hooks.json`; lifecycle host copies not double-counted)
- Findings: 5 (P0: 0 / P1: 2 / P2: 2 / P3: 1)
- Bare/empty catch: 27 in canonical sources — lifecycle 10, guard 8, `prove-stable-delivery.ts` 9. Plus 4 teardown `.catch(() => 0\|undefined)` on MCP child I/O. Non-empty catches: lifecycle `EEXIST`, guard `ENOENT` rethrow, adapter/verify-pr/delivery abort (all fail-closed).
- Fail-open sites: 3 confirmed (guard stdin exit 0; adapter unknown verdict / bad `fail-on`; MCP STALE/UNSEALED `ok: true` without high-risk=false) + 1 vacuous PASS (eval empty mean)
- Swallowed spawn failures: 0 on load-bearing paths — guard hook-surface/push-source catches return `false` → block; `verify-pr` returns child `exited`; bench throws on non-zero; delivery `exitCode ?? 1` and `gitBlob` requires 0. Teardown `.catch(() => 0)` is after the handshake verdict.
- Hook contract: lifecycle must not crash the host (empty outer catch + `exitCode = 0` + uncaughtException pin) — correct for advisory. Guard must not fail-open when enabled; decision path already fail-closed except ERR-PPLUG-01.
- `verify-pr`, compatibility, plugin/CLI builds, bench, stress shell, test-fixtures: no dummy-success catch; stress `set -u` without `-e` still asserts verdict/exit and `bad`s mismatches.

## Recommendations
1. Split hook error policy by role: lifecycle stays swallow-all; guard parse/IO failures must fail-closed when the hook is the Bash PreToolUse gate (`SEMCTX_GUARD=on` → exit 2, never exit 0).
2. Make the Action adapter a closed verdict switch: `PASS`/`WARN`/`BLOCK` only, `fail-on` in `block`/`warn`/`none` only; default deny. It is the only thing that can redden the job after `--fail-on none`.
3. In the delivery MCP smoke, treat STALE/UNSEALED as a valid fixture answer iff `canRunHighRiskControl === false`; keep refusing `isError` and unknown verdicts.
4. Eval: an empty case list is not a green gate. Fail it. Attach `cause` on the verify-pr / adapter catch paths so CI shows the original throw.
