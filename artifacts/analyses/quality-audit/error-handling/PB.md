# Error Handling — PB

## Summary
Reviewed Plane B + `core` source (`packages/core`, `semantic-model`, `semantic-dsl`, `semantic-engine`; tests skipped). The DSL never throws (`parse.ts` returns a best-effort model + diagnostics). Target JSON, UTF-8, and migration journals generally refuse. `verifyChangeContract` is fail-closed (`BLOCKED > STALE > PARTIAL > VERIFIED`); `migrateAnchors` refuses `INDEX_STALE` / `INDEX_UNSEALED` via caller authority and does not apply. No spawn. Worst issue: `formatSemanticFiles(..., true)` round-trips the partial model and overwrites `.sem` files even when parse diagnostics include errors, dropping unparsed blocks. `SemctxError` also never sets `Error.cause` — wraps stringify the inner message into `details`.

## Recommendations
1. Gate every `.sem` rewrite on `hasErrors`. `formatSemanticFiles` must not `writeAtomic` a partial parse. Treat that as the load-bearing parse/load fix; the tolerant parser can stay diagnostic-only.
2. Give `SemctxError` a real `cause`. Rethrow inner `SemctxError` in `createImmutableArtifact`; wrap only non-Semctx IO. Replace `details.cause: error.message` everywhere with `new SemctxError(..., { cause: error })`.
3. Do not collapse `readActiveChangePointer` through `.change`. Overlay and check paths should fail closed on `invalid` (reason `ACTIVE_CHANGE_POINTER_INVALID` already exists).
4. Make “could not resolve links” visible on `ok`, not only on `graphIndexed`. Keep migration’s STALE/UNSEALED refuse as the pattern.
5. Leave documented best-effort catches that rethrow (fill/close, temp unlink) and `stillSameFile` (refuse to delete). Replace the handoff empty catch and stop using empty catch to mean “treat as missing”.
