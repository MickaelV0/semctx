# Test quality — TA

## Summary
Reviewed 13 Plane A test files (`ts-analyzer/test` 7, `python-analyzer/test` 2 excluding corpus bytes, `plane-a-internal/test` 2, `workspace-analyzer-internal/test` 1, `cocoindex-adapter/test` 1). Happy-path graph/extraction tests and several fail-closed islands are real: nested-git / Git-marker `IO_ERROR`, worker malformed-DTO throws, isolated `STALE` → `INSUFFICIENT_ANALYSIS`, assembler rejection table, Python `parse-error` limitations, workspace symlink-root rejection. Worst issue: producer failure never meets the gate engine. Discovery has no `READ_FAILED` case, the sidecar test locks `status: "completed"`, and `evaluatePlaneA` only sees hand-built `analysisOutcome: "failed"` — so an unreadable file or TS parse error can still look like PASS. Isolated `UNSEALED` freshness and `.semctx`/non-git symlink containment are also untested.

## Recommendations
1. Wire one producer-failure fixture through discovery → sidecar → `evaluatePlaneA`: unreadable selected file and TS parse error must yield `READ_FAILED` / `PRODUCER_FAILED`, never `analyzed`+`completed`+PASS.
2. Add isolated `UNSEALED` (and `DIRTY_KNOWN`) rows next to the existing STALE gate-3 case; do not treat binding-absent as a freshness test.
3. Lock `.semctx` ignore and “never follow symlinks” in `discovery-selection.test.ts` the same way nested-git already is.
4. Stop pinning cocoindex `search() === []` on spawn failure; skip-or-fail the mixed-case partition instead of asserting the skip; drop the pluggy JSON hash and the assembler existence tautology.
5. Leave python-extractor limitations, symbol-grouping, ambiguous-call, and workspace root-symlink rejection as-is — they already assert consumer-visible contracts.
