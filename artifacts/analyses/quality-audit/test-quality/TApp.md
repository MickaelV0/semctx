# Test Quality — TApp

## Summary
Reviewed 73 tests under `app-services`, `apps/cli`, `mcp-server`, `context-engine`, and `repository-store` (excludes per STRATEGY). Binding gates for `HEAD_MISMATCH`, supplied-diff `SOURCE_IDENTITY_*`, and Plane-C `INDEX_STALE` are real and can fail. Health is uneven at the product gate: tests **pin** `runVerify` fail-open on admissible STALE/UNSEALED reasons, and three P0/P1 paths named in the strategy — symlink `.semctx` / `openStore` mkdir, bunfig preload, git spawn timeout — have no behavioural coverage. Worst issue is `verify-index-binding` encoding “never BLOCK when freshness cannot prove the index” as the contract, so a fail-closed fix would look like a regression and today’s STALE→PASS path stays green.

## Recommendations
1. Treat `runVerify` + CLI/MCP `semctx_verify_change` as one gate: UNSEALED always BLOCK; admissible WORKING_DIFF_MISMATCH only; remaining STALE reasons must not green-light PASS/exit 0. Replace TEST-TAPP-01’s pin and TEST-TAPP-06’s any-enum.
2. Add three P0/P1 fixtures before more plugin-delivery volume: (a) `bunfig.toml` preload sentinel with `cwd` = analyzed root, (b) symlink `.semctx` / `openStore` without init, (c) hanging git child on verify/freshness.
3. Split MCP `INVALID_ARGUMENTS` tests into schema vs public budget; cap and assert `gitDiff` string bytes.
4. Delete skip-on-symlink and 60s wall-clock “timeout” asserts; keep the real hanging-host test with a bound near 5s.
5. Stop hashing whole Plane-A graphs; assert the contested-invariant contract the golden comments already describe.
